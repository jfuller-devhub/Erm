1. ARCHITECTURE OVERVIEW
================================================================================

Technology Stack:
- Frontend: React 18+ with TypeScript
- Styling: Tailwind CSS v4 with CSS variables
- Routing: react-router (NOT react-router-dom)
- State Management:
  * AppContext (React Context) for vendors (in-memory)
  * localStorage for all other entities
- Font: Open Sans (via --font-family-primary CSS variable)

Data Persistence:
- All entities except Vendors: localStorage with versioned keys
- Vendors only: In-memory state via AppContext
- No backend database
- No API calls (all CRUD operations are client-side)

Design Philosophy:
- Follows Appian SAIL design guidelines
- All styling uses CSS variables (never arbitrary Tailwind values)
- Labels above fields, red asterisk for required fields
- Auto-save for sub-processes when user enters data
- Bidirectional many-to-many relationship updates

3.1 RISK MANAGEMENT
================================================================================

RISK
--------------------------------------------------
Fields:
  id                  : string           // Unique system identifier (e.g., "RSK-001")
  categoryId          : string           // References RiskCategory.id - classifies the risk into a domain (e.g., Information Security, Financial)
  department          : string           // Business department that owns or is primarily affected by this risk
  owner               : AppUser | null   // Risk owner responsible for monitoring and managing the risk
  title               : string           // Concise risk title or name
  description         : string           // Detailed description of the risk scenario, potential causes, and impacts
  status              : RiskStatus       // Current lifecycle status: 'draft' | 'active' | 'closed' | 'archived'
  riskType            : RiskType         // Nature of the risk: 'strategic' | 'operational' | 'financial' | 'compliance' | 'reputational' | 'cyber'
  appetiteLevel       : AppetiteLevel    // Organization's tolerance for this risk: 'averse' | 'minimal' | 'cautious' | 'open' | 'hungry'
  reviewFrequency     : ReviewFrequency  // How often this risk should be reviewed: 'monthly' | 'quarterly' | 'semi_annual' | 'annual'
  nextReviewDate      : string           // ISO date when the next risk review is scheduled
  isEnterpriseRisk    : boolean          // True if this is a top-tier enterprise-level risk visible to executive leadership
  enterpriseRiskId    : string | null    // For departmental risks: optional link to parent enterprise-level risk (references another Risk.id)
  createdAt           : string           // ISO date when risk was first identified and recorded
  createdBy           : string           // Name of person who created the risk record
  updatedAt           : string           // ISO date of most recent modification
  updatedBy           : string           // Name of person who last updated the risk record

Storage Key: erm_risks_v1
ID Pattern: RSK-###
Relationships:
  - Many-to-Many with Process (via erm_process_risk_links_v1)
  - Many-to-Many with Vendor (via erm_risk_vendor_links_v1)
  - Many-to-Many with Control (via erm_risk_control_links_v1)
  - One-to-Many with RiskAssessment
  - One-to-Many with RiskMitigationAction


RISK_CATEGORY
--------------------------------------------------
Fields:
  id                  : string           // Unique system identifier (e.g., "RCAT-001")
  name                : string           // Display name of the risk category (e.g., "Information Security")
  code                : string           // Short abbreviation or code for the category (e.g., "IS")
  description         : string           // Detailed explanation of what types of risks belong in this category
  colorHex            : string           // Display color for this category in hex format (e.g., "#C0392B") for UI badges and charts
  parentCategoryId    : string | null    // References another RiskCategory.id for hierarchical/nested categories (null for top-level)
  sortOrder           : number           // Display order sequence for consistent UI presentation

Storage Key: erm_risk_categories_v1
ID Pattern: RCAT-###

Seed Categories:
  - RCAT-001: Information Security
  - RCAT-002: Data Privacy (child of RCAT-001)
  - RCAT-003: Regulatory Compliance
  - RCAT-004: Financial Reporting
  - RCAT-005: Third-Party / Vendor
  - RCAT-006: Business Continuity
  - RCAT-007: Talent & Workforce


RISK_ASSESSMENT
--------------------------------------------------
Fields:
  id                  : string           // Unique system identifier (e.g., "ASM-001")
  riskId              : string           // References Risk.id - the risk being assessed
  assessmentType      : 'periodic' | 'triggered' | 'ad_hoc'  // Reason for assessment: scheduled periodic review, event-triggered, or one-time ad hoc
  assessmentDate      : string           // ISO date when the assessment was conducted
  likelihood          : number           // Probability of risk occurring on 1-5 scale (1=very unlikely, 5=very likely)
  impact              : number           // Severity of consequences on 1-5 scale (1=minimal, 5=catastrophic)
  riskRating          : 'critical' | 'high' | 'medium' | 'low' | 'negligible'  // Calculated overall rating based on likelihood × impact
  assessmentNotes     : string           // Detailed findings, methodology, assumptions, and rationale for scoring
  assessor            : AppUser | null   // Person who conducted the assessment
  reviewedBy          : AppUser | null   // Person who reviewed and approved the assessment (e.g., risk manager)
  reviewDate          : string | null    // ISO date when the assessment was reviewed/approved
  createdAt           : string           // ISO date when assessment record was created
  updatedAt           : string           // ISO date of most recent modification

Storage Key: erm_risk_assessments_v1
ID Pattern: ASM-###


RISK_MITIGATION_ACTION
--------------------------------------------------
Fields:
  id                  : string           // Unique system identifier (e.g., "MIT-001")
  riskId              : string           // References Risk.id - the risk this action addresses
  actionType          : 'mitigate' | 'accept' | 'transfer' | 'avoid'  // Risk treatment strategy: reduce likelihood/impact, accept as-is, transfer to third party, or eliminate
  status              : 'open' | 'in_progress' | 'complete' | 'deferred' | 'cancelled'  // Current state of the mitigation action
  priority            : 'critical' | 'high' | 'medium' | 'low'  // Urgency level for completing this action
  description         : string           // Detailed explanation of the mitigation action, steps to be taken, and expected outcome
  owner               : AppUser | null   // Person responsible for implementing and tracking the action
  dueDate             : string           // ISO date when action should be completed
  completionDate      : string | null    // ISO date when action was actually completed (null if not yet complete)
  costEstimate        : number | null    // Estimated financial cost to implement the action (null if not applicable)
  actualCost          : number | null    // Actual financial cost incurred (null until action is complete)
  notes               : string           // Additional context, dependencies, challenges, or status updates
  createdAt           : string           // ISO date when mitigation action was created
  createdBy           : string           // Name of person who created the action
  updatedAt           : string           // ISO date of most recent modification
  updatedBy           : string           // Name of person who last updated the action

Storage Key: erm_risk_mitigation_actions_v1
ID Pattern: MIT-###


3.2 PROCESS MANAGEMENT
================================================================================

PROCESS
--------------------------------------------------
Fields:
  id                  : string           // Unique system identifier (e.g., "PRC-001")
  name                : string           // Process name (e.g., "Vendor Onboarding", "Contract Lifecycle Management")
  shortDescription    : string           // Brief one-sentence summary of what the process does
  purpose             : string           // Detailed explanation of why this process exists and what business objective it serves
  scope               : string           // Boundaries defining what is included/excluded from this process
  businessDomain      : string           // Business area or department (e.g., "Procurement", "Legal", "Risk Management")
  tags                : string[]         // Keyword labels for categorization and search (e.g., ["Compliance", "Onboarding"])
  owner               : AppUser | null   // Process owner accountable for effectiveness and updates
  status              : ProcessStatus    // Current state: 'Draft' (being designed), 'Active' (in use), 'Retired' (no longer used)
  effectiveStartDate  : string           // ISO date when process became or will become active
  effectiveEndDate    : string           // ISO date when process expires or was retired (empty if currently active)
  subProcesses        : SubProcess[]     // Array of embedded sub-processes that make up this process workflow
  dependsOnProcessIds : string[]         // Array of Process.id values this process depends on or must follow
  createdDate         : string           // ISO date when process was first created
  updatedDate         : string           // ISO date when process was last modified

Storage Key: erm_processes_v2
ID Pattern: PRC-###
Relationships:
  - Many-to-Many with Risk (via erm_process_risk_links_v1)
  - Many-to-Many with Control (via erm_process_control_links_v1)


SUBPROCESS (Embedded in Process)
--------------------------------------------------
Fields:
  id                  : string           // Unique identifier for this sub-process (e.g., "SUB-001A")
  name                : string           // Name of this sub-process phase (e.g., "Vendor Application Review", "Due Diligence")
  description         : string           // Detailed description of what happens in this sub-process
  objective           : string           // Specific goal or deliverable this sub-process achieves
  boundaryStart       : string           // Trigger or entry condition that initiates this sub-process (e.g., "Vendor submits application")
  boundaryEnd         : string           // Exit condition or completion state (e.g., "Application marked as complete or rejected")
  owner               : AppUser | null   // Person responsible for this sub-process phase
  tags                : string[]         // Keywords for categorization (e.g., ["Screening", "Documentation"])
  steps               : Step[]           // Ordered array of embedded steps that comprise this sub-process workflow

ID Pattern: SUB-###[A-Z]

Note: Sub-processes are stored as embedded objects within the parent Process.
      They represent major phases or logical groupings of steps.


STEP (Embedded in SubProcess)
--------------------------------------------------
Fields:
  id                  : string           // Unique identifier for this step (e.g., "STP-001A1")
  type                : StepType         // Step type: 'Task' (action to perform), 'Decision' (branching point), 'Hand-off' (transfer to another team)
  description         : string           // Clear description of what action is performed in this step
  input               : string           // What information, documents, or conditions are required to start this step
  output              : string           // What is produced or delivered when this step completes
  entryCriteria       : string           // Conditions that must be met before this step can begin
  exitCriteria        : string           // Conditions that must be met to consider this step complete
  systemTool          : string           // Software or tool used to execute this step (e.g., "Appian Process", "DocuSign", "Excel")
  responsibleRole     : string           // Job role or title of the person who performs this step (e.g., "Vendor Coordinator", "Legal Counsel")
  sortOrder           : number           // Sequence number for ordering steps within the sub-process
  linkedStepIds       : string[]         // Array of Step.id values representing the next step(s) in the workflow (for branching/parallel paths)

ID Pattern: STP-###[A-Z][0-9]

Note: Steps are stored as embedded objects within SubProcess.
      They represent individual tasks, decisions, or handoffs in the workflow.


3.3 VENDOR MANAGEMENT
================================================================================

VENDOR (In-Memory via AppContext)
--------------------------------------------------
Fields:
  id                  : string           // Unique system identifier (e.g., "VEN-001")
  code                : string           // Business-readable unique vendor code for reference and reporting
  name                : string           // Legal or business name of the vendor organization
  category            : string           // Vendor category/type (from Configuration: Business Services, Software/Hardware, etc.)
  status              : string           // Current vendor relationship status (from Configuration: Active, Inactive, Pending Review, etc.)
  contactName         : string           // Full name of primary vendor contact person
  contactEmail        : string           // Primary contact's email address
  contactPhone        : string           // Primary contact's phone number
  addressLine1        : string           // First line of vendor's physical business address
  addressLine2        : string           // Second line of address (suite number, building, floor, etc.)
  city                : string           // City where vendor is located
  state               : string           // State, province, or region where vendor is located
  zipCode             : string           // Postal code or ZIP code
  country             : string           // Country where vendor is headquartered or operates
  website             : string           // Vendor's primary website URL
  notes               : string           // Free-form internal notes, observations, or special instructions about the vendor
  productIds          : string[]         // Array of Product IDs that this vendor provides or supports (many-to-many relationship)
  classificationScore : number | null    // Auto-calculated risk score (0-100) based on weighted classification category levels
  vendorLevelId       : string | null    // Auto-assigned vendor tier/level ID based on classification score thresholds (references VendorLevel.id)
  createdDate         : string           // ISO date when vendor record was first created
  updatedDate         : string           // ISO date when vendor record was last modified

Storage: In-memory only (AppContext)
ID Pattern: VEN-###
Relationships:
  - Many-to-Many with Risk (via erm_risk_vendor_links_v1)
  - Many-to-Many with Product (via productIds field)
  - Many-to-One with VendorLevel (via vendorLevelId)


VENDOR_LEVEL
--------------------------------------------------
Fields:
  id                  : string           // Unique system identifier (e.g., "VL-001")
  levelNumber         : number           // Tier number (typically 1-5, with 5 being highest risk/criticality)
  levelName           : string           // Display name for this vendor tier (e.g., "Critical Vendor", "High Risk Vendor")
  description         : string           // Detailed explanation of what qualifies a vendor for this level and oversight requirements
  minScore            : number           // Minimum classification score (0-100) required for auto-assignment to this level
  maxScore            : number           // Maximum classification score (0-100) for this level (ranges must not overlap)
  color               : string           // Display color for UI badges and charts (CSS variable or hex code)
  sortOrder           : number           // Display order sequence
  createdAt           : string           // ISO date when level was created
  createdBy           : string           // Name of person who created this level
  updatedAt           : string           // ISO date of most recent modification
  updatedBy           : string           // Name of person who last updated this level

Storage Key: erm_vendor_levels_v1
ID Pattern: VL-###

Seed Levels:
  - VL-001: Critical Vendor (80-100)
  - VL-002: High Risk Vendor (60-79)
  - VL-003: Moderate Risk Vendor (40-59)
  - VL-004: Low Risk Vendor (20-39)
  - VL-005: Minimal Risk Vendor (0-19)


VENDOR_CLASSIFICATION (Category)
--------------------------------------------------
Fields:
  id                  : string           // Unique system identifier (e.g., "VCLS-001")
  title               : string           // Name of classification category (e.g., "Vendor Risk Assessment", "Data Security Classification")
  description         : string           // Explanation of what this classification category evaluates
  weight              : number           // Percentage weight (0-100) this category contributes to overall vendor classification score
  createdAt           : string           // ISO date when classification category was created
  createdBy           : string           // Name of person who created this category
  updatedAt           : string           // ISO date of most recent modification
  updatedBy           : string           // Name of person who last updated this category

Storage Key: erm_classification_categories_v1
ID Pattern: VCLS-###

Note: Weights across all active classifications must sum to exactly 100%.
      Each vendor's overall classification score is calculated as the weighted
      average of their scores across all classification categories.


VENDOR_CLASSIFICATION_LEVEL (Scoring Matrix)
--------------------------------------------------
Fields:
  id                  : string           // Unique system identifier (e.g., "VCL-001")
  classificationId    : string           // References VendorClassification.id - the parent classification category
  levelNumber         : number           // Level tier (typically 1-5, with 5 being highest exposure/risk)
  levelLabel          : string           // Display label for this level (e.g., "Level 5 - High Exposure", "Level 3 - Moderate Exposure")
  description         : string           // Detailed criteria defining when a vendor qualifies for this level (e.g., spend thresholds, data access, criticality)
  score               : number           // Point value (0-100) assigned to vendors at this level for weighted score calculation
  sortOrder           : number           // Display order sequence
  createdAt           : string           // ISO date when level was created
  createdBy           : string           // Name of person who created this level
  updatedAt           : string           // ISO date of most recent modification
  updatedBy           : string           // Name of person who last updated this level

Storage Key: erm_vendor_classification_levels_v1
ID Pattern: VCL-###

Note: Each classification category has multiple levels (scoring bands). When a vendor
      is assessed, they are assigned a level within each category, and that level's
      score is weighted to calculate their overall classification score.

VENDOR_LEVEL_CHECKLIST_ASSOCIATION

3.4 REGULATORY COMPLIANCE
================================================================================

REGULATION
--------------------------------------------------
Fields:
  id                      : string       // Unique system identifier (e.g., "REG-001")
  regulationNumber        : string       // Official regulation identifier (e.g., "HR-1234", "EU-GDPR-2016/679", "21 CFR Part 11")
  title                   : string       // Full official title of the regulation
  description             : string       // Detailed explanation of what the regulation covers and requires
  regulatoryBody          : string       // Government agency or body that issued the regulation (e.g., "SEC", "EU Parliament", "FDA", "FINRA")
  jurisdiction            : string       // Geographic or legal scope (e.g., "Federal - USA", "EU", "California", "New York State")
  category                : string       // Regulation type from Configuration (e.g., "Financial", "Privacy", "Safety", "Environmental")
  impactLevel             : 'critical' | 'high' | 'medium' | 'low'  // Assessment of business impact severity
  status                  : RegulationStatus  // Our internal tracking status: monitoring, in-review, in-progress, compliant, non-compliant, not-applicable, archived
  stage                   : RegulationStage   // Regulation's legislative lifecycle: proposed, committee, passed, effective, amended, repealed
  proposedDate            : string | null     // ISO date when regulation was first proposed
  publicationDate         : string | null     // ISO date when regulation was officially published
  effectiveDate           : string | null     // ISO date when regulation becomes/became enforceable
  complianceDeadline      : string | null     // Internal deadline for achieving compliance (may differ from effective date)
  reviewDate              : string | null     // Next scheduled date for reviewing compliance status
  primaryOwner            : AppUser | null    // Compliance officer or subject matter expert responsible for this regulation
  stakeholders            : AppUser[]         // Cross-functional team members involved in compliance efforts
  department              : string            // Primary business department affected or responsible
  relatedBillIds          : string[]          // Array of Bill.id values for legislation that created or modified this regulation
  linkedControlIds        : string[]          // Array of Control.id values - controls that help achieve compliance (also linked via junction table)
  supersedes              : string | null     // References Regulation.id of previous regulation this replaces
  supersededBy            : string | null     // References Regulation.id of newer regulation that replaces this one
  complianceStatus        : ComplianceStatus  // Progress toward compliance: not-started, assessment, planning, implementing, testing, compliant, partial, non-compliant
  gapAnalysisCompleted    : boolean           // True if gap analysis has been performed to identify compliance deficiencies
  readinessScore          : number            // Assessment of compliance readiness on 0-100 scale
  estimatedCost           : number | null     // Projected financial cost to achieve compliance (null if not estimated)
  officialUrl             : string | null     // Link to official regulation text or government website
  attachmentIds           : string[]          // Array of document IDs for related materials (guidance, interpretations, etc.)
  tags                    : string[]          // Keywords for categorization and search
  createdAt               : string            // ISO date when regulation record was created
  createdBy               : string            // Name of person who created the record
  updatedAt               : string            // ISO date of most recent modification
  updatedBy               : string            // Name of person who last updated the record

Storage Key: erm_regulations_v1
ID Pattern: REG-###

Enums:
  RegulationStatus: 'monitoring' | 'in-review' | 'in-progress' | 'compliant' |
                    'non-compliant' | 'not-applicable' | 'archived'

  RegulationStage: 'proposed' | 'committee' | 'passed' | 'effective' |
                   'amended' | 'repealed'

  ComplianceStatus: 'not-started' | 'assessment' | 'planning' | 'implementing' |
                    'testing' | 'compliant' | 'partial' | 'non-compliant'

Relationships:
  - Many-to-Many with Control (via erm_regulation_control_links_v1)
  - Many-to-Many with ComplianceRequirement (via erm_regulation_requirement_links_v1)

COMPLIANCE_REQUIREMENT

3.5 CONTROL MANAGEMENT

CONTROL
--------------------------------------------------
Fields:
  id                  : string           // Unique system identifier (e.g., "CTL-001")
  owner               : AppUser | null   // Person responsible for executing or monitoring this control
  department          : string           // Business department that operates this control
  name                : string           // Concise name of the control activity
  description         : string           // Detailed explanation of what the control does and how it operates
  controlType         : ControlType      // Nature of control: preventive, detective, corrective, directive, or compensating
  frequency           : ControlFrequency // How often control is executed: continuous, daily, weekly, monthly, quarterly, annual
  effectiveness       : ControlEffectiveness  // Most recent assessment: effective, partially_effective, ineffective, not_tested
  isAutomated         : boolean          // True if control is automated/system-enforced, false if manual
  lastTestedDate      : string           // ISO date when control effectiveness was last tested
  nextTestDate        : string           // ISO date when next control test is scheduled
  status              : ControlStatus    // Current state: active, inactive, in_design, deprecated
  frameworkRef        : string           // Reference to external control framework (e.g., "NIST 800-53 AC-2", "ISO 27001 A.9.2.1")
  createdAt           : string           // ISO date when control was created
  updatedAt           : string           // ISO date of most recent modification

Storage Key: erm_controls_v1
ID Pattern: CTL-###

Enums:
  ControlType: 'preventive' (prevents issues before they occur) |
               'detective' (identifies issues after they occur) |
               'corrective' (fixes issues that occurred) |
               'directive' (mandates specific actions) |
               'compensating' (alternative when primary control unavailable)

  ControlFrequency: 'continuous' | 'daily' | 'weekly' | 'monthly' | 'quarterly' | 'annual'

  ControlEffectiveness: 'effective' | 'partially_effective' | 'ineffective' | 'not_tested'

  ControlStatus: 'active' | 'inactive' | 'in_design' | 'deprecated'

Relationships:
  - Many-to-Many with Process (via erm_process_control_links_v1)
  - Many-to-Many with Risk (via erm_risk_control_links_v1)
  - Many-to-Many with ComplianceRequirement (via erm_control_requirement_mappings_v1)
  - Many-to-Many with Regulation (via erm_regulation_control_links_v1)

Note: Controls are activities or mechanisms designed to mitigate risks and ensure
      compliance with regulations and requirements.

  version                 : string       // Version or edition of the framework (e.g., "2013", "v2.0")
  governingBody           : string       // Organization that maintains the framework (e.g., "AICPA", "ISO", "NIST")

  certificationRequired   : boolean      // True if organization must obtain formal certification/attestation

KEY_RISK_INDICATOR (KRI)
--------------------------------------------------
Fields:
  id                  : string           // Unique system identifier (e.g., "KRI-001")
  name                : string           // Name of the risk indicator (e.g., "Overdue Control Tests", "Unmitigated High Risks")
  description         : string           // Explanation of what this KRI measures and why it matters
  owner               : AppUser | null   // Person responsible for monitoring and reporting on this KRI
  category            : string           // KRI grouping (e.g., "Control Effectiveness", "Risk Exposure", "Compliance")
  status              : 'green' | 'amber' | 'red' | 'no_data'  // Current health status based on threshold comparison
  currentValue        : number           // Most recent measured value
  targetValue         : number           // Desired or acceptable value
  threshold1          : number           // Warning threshold (triggers amber status)
  threshold2          : number           // Critical threshold (triggers red status)
  thresholdDirection  : 'lower_is_better' | 'higher_is_better'  // Whether lower or higher values are preferred
  calculationSource   : string           // How value is derived (see enumeration below)
  measurementUnit     : string           // Unit of measurement (e.g., "count", "percentage", "days")
  frequency           : string           // How often KRI is updated (e.g., "Daily", "Weekly", "Monthly")
  lastUpdated         : string           // ISO date when currentValue was last refreshed
  trend               : 'improving' | 'stable' | 'worsening' | 'unknown'  // Direction of change over time
  linkedRiskIds       : string[]         // Array of Risk.id values this KRI relates to
  createdAt           : string           // ISO date when KRI was created
  updatedAt           : string           // ISO date of most recent modification

Storage Key: erm_kris_v1
ID Pattern: KRI-###

CalculationSource values:
  - 'auto_overdue_control_tests' (automatically counts controls past their test date)
  - 'auto_ineffective_controls' (counts controls rated as ineffective/partially effective)
  - 'auto_open_high_critical_risks' (counts active risks with high or critical severity)
  - 'auto_overdue_risk_reviews' (counts risks past their review date)
  - 'auto_unmitigated_risks' (counts risks without approved mitigation plans)
  - 'auto_control_coverage' (calculates percentage of risks with linked controls)
  - 'manual' (manually entered/updated value)

Note: KRIs provide early warning signals of increasing risk exposure or degrading
      control effectiveness, enabling proactive risk management.
